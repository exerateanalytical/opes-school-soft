# Routes, detail pages, tabs and broken flows — audit

**Date:** 2026-08-13 · **Branch:** `main` @ `c1ccba2` · **App:** http://localhost:8931 (preview `opes`)
**Scope:** audit only. No application code was changed.

## Method

1. `php artisan route:list --json` → 213 named routes; 108 static (non-parameterised) GET routes in the web shell.
2. Logged in via the DEMONSTRATION panel as **administrator, principal, bursar, accountant, registrar, teacher, guardian**. For each role: read the sidebar out of `/dashboard`, then `fetch()`-ed every sidebar href and recorded the status.
3. **Link-graph crawl** as administrator: BFS from `/dashboard` over every same-origin `<a href>`, **244 pages fetched**, recording the inbound-link set for every URL. A URL with an empty inbound set is reachable only by typing it.
4. Separate BFS over the guardian portal: **85 pages, all 200, zero orphans** (contrast with the staff shell below).
5. Static corroboration: `grep -rn "route('…'|url('/…'|href=\"/…\"" resources/views app` for every suspect route, plus DB reads via `artisan tinker`.

Every row below cites a URL actually fetched, a crawl result, or a grep actually run.

## Not checked

- **Screenshots.** `computer{action:"screenshot"}` failed throughout ("the Browser pane is not displayed, so the page is not compositing frames"), and `resize_window` to 1440x900 immediately before each attempt did not help. All "renders real content vs empty state" judgements are therefore based on fetched HTML and extracted `<main>` text length, not on looking at pixels. **Visual/layout defects are out of scope of this audit.**
- **Rows that could not be exercised because the demo data is empty:** `/admissions` (0 applications), `/procurement/requisitions`, `/procurement/invoices`, `/procurement/payments` (0 rows each), `/results`, `/homework`, `/communication/outbox`, `/communication/templates`, `/guardians/pta`. Their row-link wiring was read from the blade templates instead where noted, but not observed rendering.
- **POST/write flows.** Nothing was submitted — no form was posted, no wizard advanced, no record created. "A create form with no post-create destination" could therefore only be assessed statically (e.g. `/users/create`, `/ledger/journal-entries/create`, `/procurement/*/capture` were fetched but not submitted).
- **The 10-step rollover wizard** and the **promotion wizard** were fetched (200, step bars render) but not driven through their steps.
- **Roles not exercised:** `staff_portal` (only `/portal/staff` = 403 from the admin shell was confirmed), vice-principal, super administrator, and the remaining ~14 seeded roles.
- **Print/document routes** (`*/print`, `*/voucher`, `*/receipt`) were excluded from the crawl to avoid generating documents; their inbound links were verified by grep only.
- **A crawl artefact to be aware of:** roughly 90 URLs returned `ERR` mid-crawl from connection exhaustion against the dev server (students/*, guardians/*, finance/statement/*, examinations/*, etc.). Those pages' *outbound* links were therefore not harvested, so the orphan set above is a **lower bound** — every listed orphan was additionally confirmed by grep, but there could in principle be more.
