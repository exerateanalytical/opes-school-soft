# Visual consistency audit — 2026-08-13

**Scope:** desktop 1440×900 and mobile 375×812, roles administrator / accountant /
teacher, across `/dashboard`, `/students`, `/finance/invoices`, `/staff`,
`/library`, `/visitors`, `/settings`, `/academics/settings`, `/attendance`,
`/users`, `/inventory`, `/payroll`, `/timetable`, `/reports`, `/finance/dashboard`
and the detail pages `/students/1`, `/library/books/1`, `/welfare/discipline`,
`/admissions/wizard`.

**Method:** headless Chrome over CDP (`scratchpad/shot.mjs`, `crop.mjs`, plus
`m2–m5.mjs` measurement passes written for this audit). Every finding below was
**looked at in a screenshot**; the pixel figures come from a matching DOM
measurement. Audit only — nothing was changed.

---

## What the restyle DID fix (verified, do not re-litigate)

- **Page-title size is now uniform.** `h1` measures `29.75px/700` on all 14
  screens sampled. The two-title-size problem is gone.
- **Page height no longer runs to 2585px.** The sidebar sticky fix held.
  Trailing void below content is now 56–57px on content-rich screens.
- **Dark table header is the default** on 8 of 10 list screens sampled
  (`rgb(6,50,28)` on white text).

## The five themes, in order of leverage

1. **The KPI card component was built and never adopted.** 42 screens use
   `x-kpi-card`; **1 passes `tone`, 0 pass `sub`, 0 pass `spark`, 2 pass
   `delta`**, and **39 still use the legacy `icon-bg` escape hatch**. Result:
   every screen renders the same mint card with a fully-saturated icon in an
   unrelated hue, no second line, no trend, no sparkline — i.e. none of the
   three things the brief identified as making the references look "built".
2. **The right rail is 83–91% empty on the biggest screens** — a 238px column
   of blank canvas running the full height of the table (`/users` 2721px empty,
   `/staff` 1356px, `/library` 996px), while the table beside it is squeezed to
   862px and wraps five of its eight columns. This is the "empty and cramped at
   the same time" complaint in one defect.
3. **Nothing shared covers detail and dashboard screens.** 46 files use
   `x-list-screen`; **91 files hand-roll their own `<h1>` header**. Every
   hand-rolled screen re-invents radii, section headings, button hierarchy and
   rails, which is where all the cross-screen inconsistency comes from.
4. **Roles land on broken dashboards.** Teacher gets one full-width KPI card
   whose value is an em dash, plus a raw `LedgerIntegrityCheck` authorization
   exception. Accountant gets zero KPI cards. Administrator gets five, two of
   which are em dashes.
5. **Mobile list screens clip their KPI strip.** `min-w-max grid-cols-2` makes
   the strip wider than 375px on every `x-list-screen` page, so card 2 is cut
   in half behind a horizontal scrollbar. The dashboard (not a list screen)
   stacks correctly — so the same component behaves two ways.

## Recommended order

Everything in **section A** first, in this order — A1, A2, A3, A4 (the KPI row is
on 42 screens and is the first thing anyone sees), then A5/A6/A7 (the rail-void /
squeezed-table / wrapping-pill triangle, which is the whole "cramped *and* empty"
complaint), then A8/A9/A18/A19 (mobile), then A10–A13 (row actions, density,
header, radii), then A20–A25.

Section B splits: B1/B2/B3 (role dashboards) and B6/B7 (dead navigation) are the
two things a prospect would call unfinished within ten seconds, and neither is
fixable at the component layer. B8 and B10 are the two screens the user named.
