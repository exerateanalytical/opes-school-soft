## ⚠ DECISION NEEDED FROM THE DESIGN OWNER

**The platform's own default colours fail WCAG AA.** Measured with the new
`ColorContrast` class and re-verified by hand:

| Token | Hex | Contrast on white | AA (4.5:1) |
|---|---|---|---|
| `warning` | `#D99A20` | **2.44 : 1** | ✗ fails |
| `danger` | `#D64545` | **4.38 : 1** | ✗ fails |
| `primary` | `#0B5A32` | 8.32 : 1 | ✓ passes |

These are not hypothetical — `bg-warning-bg text-warning` is a real pattern in
the codebase. The consequence is that **a fresh install shows a contrast
warning on its own branding screen**.

The implementing agent kept the check honest rather than weakening the
threshold to make the test pass, which was the right call. Darkening the
shipped amber and red is a brand decision, so it is queued rather than taken:
`#D99A20` needs roughly `#8A6100` and `#D64545` roughly `#C02B2B` to clear 4.5,
but those are starting points, not a designer's answer.

## Two traps found the hard way (now documented in the code)

1. **A `@php` written inside a Blade `{{-- --}}` comment takes every page down**
   with a `ParseError` — Blade compiles directives *before* it strips comments.
   The plan's own suggested comment text contained one. Noted in the layout.
2. **The plan's "Heritage default raises no contrast warning" assertion was
   arithmetically false** (see the table above). The test was rewritten to
   assert what must actually hold.

## Nine plan deviations, each verified against real code
No `setup_checklist_items` table (readiness is evaluated live via Operations'
`EvaluateSetupReadiness`); `licences.expires_at` not `expires_on`; an
`opes.settings_hub` lang block already existed (merged, not duplicated —
PHP's last-key-wins would have silently overridden it); the plan's tests used
the wrong roles throughout (`Principal` holds `setting.view` but not
`setting.edit`; `Bursar` lacks `setting.view` entirely); only 2 of 3 nav icons
were missing; `SettingsRegistryTest` was already failing on `main`; MySQL
normalises JSON key order; the plan's indigo preset carried a non-ASCII digit;
and the pre-existing `BrandingTest` broke because the plan never mentioned it.
