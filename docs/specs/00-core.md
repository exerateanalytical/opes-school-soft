## 2. Product definition

A school management platform for Cameroon: **Laravel + MySQL**, API-first, domain-driven, with a responsive Livewire frontend in the same codebase.

**Market:** any Cameroonian school — nursery only, primary only, secondary only, technical, teacher-training, or any combination; Anglophone, Francophone, or bilingual.

**Tenancy:** single school per deployment. One product, many isolated instances.

**Not in v1:** live payment-gateway collection; multi-tenant SaaS hosting; any national credential document (§13).

## 3. Deployment topology

**Both modes are supported and must be designed for from Phase 0.**

| | **LAN (default)** | **VPS (option)** |
|---|---|---|
| Host | Mini-PC/server in the school | Vendor-managed VPS |
| Clients | Browsers on school LAN/Wi-Fi | Browsers over internet |
| Internet | **Not required for any core function** | Required |
| TLS | Per-school local CA, generated by installer, one-click client trust | Let's Encrypt |
| Backup | USB rotation + optional cloud when online | Automated offsite |
| Updates | USB folder or HTTPS feed, admin-confirmed | Vendor-pushed |
| Parent portal | Unavailable, or via reverse tunnel | Available |

**LAN-first is a product commitment, not an accident.** The .NET reference is genuinely offline-first (two classes in the entire codebase open a socket, both opt-in). Every internet-dependent feature — SMS, WhatsApp, email, licence activation, update feed, QR verification — **degrades to a queued outbox or a disabled menu item with a clear message. Never a blocking error, never a hang.** CI must boot the app with all outbound network blocked and run the core workflows.

**Reference hardware (LAN):** 4-core CPU, 8 GB RAM, SSD, **UPS required**.

**Power durability is mandatory, not tuning.** The shipped MySQL config sets `innodb_flush_log_at_trx_commit=1` and `sync_binlog=1`, asserted by preflight. A receipt is rendered **only after the DB commit returns** — never optimistically. Cameroon's power reality makes this a correctness requirement.

Detail in `08-operations`.

## 6. Architecture

### 6.1 Layering

Business logic lives in framework-agnostic **Action** classes. REST and Livewire are both thin adapters over the same Actions. The UI does **not** call the HTTP API over the network.

```
app/Modules/<Module>/
├─ Domain/      pure rules, value objects. No Laravel, no Eloquent.
├─ Actions/     use cases. The ONLY way business state changes.
├─ Models/      Eloquent. Persistence only.
├─ Http/        Controllers, FormRequests, Resources
├─ Livewire/    UI components
├─ Policies/  Events/  Listeners/
└─ Database/    migrations, factories, seeders
```

### 6.2 Enforced rules

1. `Domain/` imports no Laravel or Eloquent.
2. Cross-module access goes **only** through the owning module's Actions or published Events. This binds every layer, including `Actions/` — resolving a v1 ambiguity where two rules disagreed about whether Actions could reach across.
3. Every Action authorizes before it mutates.
4. Every state-mutating Action runs in a DB transaction.
5. **Cross-module Actions must expose batch signatures** (`forEnrollments(array $ids)`). Calling a single-entity cross-module Action inside a loop is a review-blocking defect — rule 2 otherwise manufactures N+1 behind a clean interface.
6. **Events that trigger posting or side effects dispatch after commit** (`ShouldDispatchAfterCommit`). Enforced by architecture test. Without this a queue worker can process a job before its transaction commits, or after it rolls back.
7. **Idempotency lives in the Action layer, not HTTP middleware.** Every mutating Action accepts an `idempotency_key`, unique-indexed in a request log. HTTP middleware merely supplies the key; Livewire generates one per form instance. A v1 rule that put idempotency only on API writes left the double-clicked cashier button — the actual failure — unprotected.
8. **No unbounded collection query reaches a Blade view.** `Model::preventLazyLoading()` outside production.

## 7. Numeric policy

### 7.1 Money

**`BIGINT SIGNED`, whole FCFA.** Not `UNSIGNED` — v1 mandated unsigned while simultaneously requiring signed fee adjustments, disposal gains/losses, and cash variances, and its own balance formula underflowed. MySQL 8 raises `ERROR 1690` on unsigned subtraction below zero, so **the first overpayment threw a 500**.

- `CHECK (amount >= 0)` only where a magnitude is genuinely non-negative (`Payment.amount`, `InvoiceLine.amount`).
- Balance arithmetic happens in PHP through `Money`, never in SQL.
- No `FLOAT`, no `DECIMAL` for money. Architecture test enforced, with an explicit allow-list rather than weakening the rule.
- Ledger amounts use `debit`/`credit` columns (both non-negative) — the accounting-correct representation of sign.

### 7.2 Rates and percentages

**Integer basis points** (`BIGINT`; 4.2% = `4200` per 100 000). A CNPS rate stored as `DOUBLE` yields different francs on different runs, which breaks the §5 reproducibility guarantee that payroll depends on. The money architecture test extends to rate columns.

### 7.3 Allocation and rounding

`Money::allocate(array $ratios): Money[]` — **largest-remainder**, with `Σ parts === total` asserted inside the value object. Property test: for all totals 1…1 000 000 and all ratio vectors, the sum is conserved.

Rules:
- The **last instalment absorbs the residual**.
- In a generated journal entry, the **balancing line is `total − Σ(other lines)`**, never independently rounded.
- Payroll rounds **once, at component level**, half-up to 1 FCFA. Invariant test: `gross − Σdeductions = net`, exactly, every payslip.
- Straight-line depreciation absorbs the remainder in the final period so accumulated depreciation exactly equals `cost − residual`.

### 7.4 Scores

`DECIMAL(6,3)`. Computed in decimal, never float. **Round half-up to 2 dp once, at the end of aggregation; rank and band on the rounded value**, so the printed number always explains the rank and the mention. Precision is configurable per report-card config.

### 7.5 Dates and time

Store UTC; `app.timezone = Africa/Douala` (UTC+1, no DST). A single `business_date()` helper is used by attendance, cash-desk close, and daily-collections — `now()->toDateString()` in UTC is wrong between 00:00 and 01:00 local. Locale-aware formatting: FR `1 234,50` / `dd/mm/yyyy`, EN `1,234.50`.

## 8. Academic structure

v1 referenced these ~40 times and defined none, so Phase 1 could not start.

```
AcademicYear
├─ code, name, starts_on, ends_on, is_current
├─ status (planned|active|closed)
└─ INVARIANT: years are CONTIGUOUS and GAPLESS — year N ends the day
   before year N+1 starts. Every calendar date resolves to exactly one
   academic year.
```

> **Why gapless matters.** v1 described academic years as "roughly September–July," which left **August belonging to no academic year** — while requiring every ledger entry to carry an `academic_year_id`. August payroll, supplier invoices and depreciation had nowhere to go.

```
SchoolSection
├─ education_level (nursery|primary|secondary_1|secondary_2|technical|teacher_training)
├─ track (general|technical|normal)
├─ sub_system (anglophone|francophone)
├─ name, name_fr, matricule_format, display_order, is_active
└─ UNIQUE(education_level, track, sub_system)

ClassLevel      school_section_id, code, name, name_fr, order_index,
                is_exam_class, UNIQUE(school_section_id, code)

Stream          school_section_id, code, name, name_fr,
                subject_basket (drives ranking cohort), is_active

ClassGroup      class_level_id, stream_id (nullable), academic_year_id,
                name, class_teacher_staff_id, room_id, capacity, status
                UNIQUE(academic_year_id, class_level_id, name)

House           code, name, colour, patron_staff_id
Department      code, name, name_fr, head_staff_id
Room            code, name, capacity, building, type
```

`Stream.subject_basket` is load-bearing: ranking students against a different elective set is arithmetically unfair and a Cameroonian conseil de classe will reject it. See `01-assessment`.

### 9.1 Roles

v1 said "fixed roles + granular permissions" and never listed them — so the authorization test suite it promised could not be written.

| Role | Scope |
|---|---|
| Super Admin | Everything incl. licensing, restore, settings |
| Administrator | Everything except licensing and restore |
| Principal / Proviseur | Read-all + approvals + publication |
| Vice-Principal / Censeur | Academics + discipline approvals |
| Registrar | Students, guardians, enrollment, admissions |
| Bursar | Fee collection, receipts, cash desk |
| Accountant | Ledger, statements, procurement, tax |
| HR Officer | Staff, contracts, leave |
| Payroll Officer | Payroll runs, declarations |
| Exams Officer | Exams, marks validation, report cards |
| Class Master | Own class marks, remarks, conseil |
| Teacher | Own assigned class × subject marks, own timetable |
| Discipline Master | Discipline cases, sanctions |
| Librarian | Library |
| Store Keeper | Inventory, assets |
| Nurse | Medical |
| Transport Officer / Hostel Warden | Welfare sub-domains |
| Front Desk | Visitors |
| Guardian *(portal)* | Own children, read-only |
| Staff *(portal)* | Own payslips, leave, timetable |

Roles are seeded with permission sets; **every permission is individually grantable**. `User.status` includes `suspended`.

### 9.2 The guardian boundary

The highest-risk authorization surface. `StudentGuardian` carries `relationship, is_primary, has_custody, receives_reports, receives_invoices, valid_from, valid_to`, and the **explicit mapping from flag → visible scope** lives in `07-students`. Access is gated on `NOW()` within the validity window, so a custody change neither deletes history nor leaves stale access.

Tested by a **deny-by-default route enumeration suite**: walk every route and Action, assert a guardian is denied unless explicitly allow-listed. A hand-written test misses the route added next sprint.

### 9.3 Recovery

Password reset **must not depend on a channel the school does not have.** Most Cameroonian schools have no SMTP.

- **Primary:** an administrator sets another user's password directly, audited, forced change on next login.
- **Break-glass:** `RecoveryCredential` — ported from the reference, with its two gaps fixed. ~98 bits from a Crockford-style alphabet (no `0/O/1/I/L/U`), stored only as Argon2id, single-active, **expires after 12 months**, **true single-use with forced regeneration**, logs in as the earliest active Administrator, fully audited. Never a shared vendor secret.
- The setup wizard prints a **recovery sheet** (recovery code, `APP_KEY`, backup encryption key, instance UUID) for the proprietor's safe.
- `artisan opes:promote-admin` as a vendor escape hatch requiring server access.

### 9.4 Secrets

Passwords: Argon2id. Optional TOTP 2FA. Configurable session timeout with an **idle lock screen** (fast password re-entry preserving form state), not a full logout — a shared front desk needs both security and workflow continuity.

**`APP_KEY` custody is a data-loss landmine and gets a written procedure.** Field-level encryption derives from it: lose it and that data is unrecoverable *even from a perfect backup*; back it up alongside the dump and the encryption is decorative against the threat it exists for. Key on the recovery sheet, in the school's safe, escrowed with the vendor under documented process, excluded from routine backups, `APP_PREVIOUS_KEYS` rotation defined, and a **startup canary decrypt** that refuses to boot on a wrong key rather than corrupting data silently.

### 9.5 Encrypted fields

Medical notes, national ID numbers, bank details, **genotype, blood group, religion**. In Cameroon genotype is sickle-cell status — health data about a child, and v1 left it in a plain column.

Encrypted columns cannot be indexed or made unique with Laravel's non-deterministic encryption, so `CNPS_number` (needed for the DIPE export) and `national_id_number` (needs uniqueness) carry **blind index** columns (`HMAC-SHA256(value, key)`). Audit payloads for encrypted fields are themselves encrypted and excluded from exports and logs.

## 10. Constraints & integrity

v1 specified **one** UNIQUE constraint, zero `ON DELETE` behaviours, zero CHECK constraints.

### 10.1 "One active X" — MySQL pattern

MySQL 8 has no partial indexes. Use a stored generated column:

```sql
active_year_key BIGINT AS (CASE WHEN status='active' THEN academic_year_id END) STORED,
UNIQUE KEY uq_active_enrollment (student_id, active_year_key)
```

Required for: active enrollment per student-year · primary guardian per student · transport allocation · hostel allocation · open library issue per copy · active contract per staff (where single-contract).

### 10.2 Both-directions constraints

v1 said hostel allocations are "one active per student" — preventing a student holding two beds, but **not two students holding one bed**, which is the actual clerical race. Every allocation is constrained on **both** sides, plus capacity:

| Resource | Constraints |
|---|---|
| Hostel bed | one active per student **and** one active per bed |
| Transport seat | one active per student **and** `Route.capacity` enforced under lock |
| Library copy | one open issue per copy **and** per-member limit |
| Class group | `capacity` enforced on enrollment |

### 10.3 Ledger

- `CHECK ((debit = 0) <> (credit = 0))` — exactly one non-zero side.
- Σdebit = Σcredit is multi-row, so it is verified in-Action under `SELECT … FOR UPDATE` on the entry, **plus** BEFORE INSERT/UPDATE/DELETE triggers on `JournalEntryLine` rejecting any write where the parent is `posted` or `reversed`, **plus** a nightly integrity job reporting any unbalanced entry.
- `UNIQUE(source_type, source_id, posting_rule_id)` on `JournalEntry` — the idempotency backstop against replayed queue jobs.

### 10.4 Idempotency constraints

`UNIQUE(asset_id, fiscal_year_id, period_month)` on `DepreciationSchedule` · `UNIQUE(payroll_month, staff_member_id)` across all runs · `UNIQUE(class_group_id, academic_year_id)` on promotion runs · `UNIQUE(enrollment_id, fee_structure_id, term_id)` on `Invoice`.

Status transitions use **conditional UPDATE with affected-rows check** (`WHERE status = 'calculated'`), never read-then-write.

### 10.5 Deletion matrix

| Treatment | Applies to |
|---|---|
| **RESTRICT** | Student, Enrollment, Subject, SubjectAllocation, AssessmentPeriod, AcademicYear, ChartOfAccount, Journal, FiscalYear, Asset, FeeItem, PostingRule, StatutoryRate, Supplier — anything with financial or academic history |
| **Archive flag** (`is_archived`, never `SoftDeletes`) | Reference data with unique codes. Laravel `SoftDeletes` + UNIQUE means a deleted code permanently blocks re-creation |
| **Never cascade into** | Mark, Invoice, Payment, JournalEntry(+Line), PayrollItem, DepreciationSchedule, AuditLog, DocumentPrintLog |

**Actor FKs** (`entered_by`, `posted_by`, `received_by`, `voided_by`, `approved_by`…) are RESTRICT; users are deactivated, never deleted. `AuditLog` and `DocumentPrintLog` additionally denormalise `actor_name_at_time`, so the record stays legible after a rename.

### 10.6 Optimistic locking

`version` columns on `Mark` and `Invoice`. Conditional `UPDATE … WHERE version = ?`; on 0 affected rows, show **what changed and who changed it** rather than overwriting. Two teachers on one class's marks currently means silent last-write-wins.

## 11. Concurrency

For every contested resource, the row that gets locked:

| Operation | Lock |
|---|---|
| Payment allocation | `SELECT … FOR UPDATE` on `Invoice`, recompute outstanding **inside** the lock |
| Period publication | `FOR UPDATE` on `PeriodPublication`; set `publishing`, validate, snapshot, commit. Marks entry takes a shared lock and rejects unless `open` |
| Bed / seat / library copy | `FOR UPDATE` on the resource row |
| Payroll run | `FOR UPDATE` on the run + advisory lock on `(employer, payroll_month)`; `inputs_hash` stored at calculate, re-verified at approve — **approval fails if any input changed** |
| Depreciation run | `FOR UPDATE` on `DepreciationRun` |
| Promotion run | `FOR UPDATE` on the run record |
| Accounting period | Posting takes a shared lock; locking takes it exclusively |
| Sequences | See §12 |

## 12. Sequences & numbering

Two different obligations, and v1 conflated them.

**Gapless (OHADA AUDCIF Art. 19 requires continuous numbering):** `JournalEntry.piece_no`. Allocated **only at the moment of posting, never at draft creation**, from a `Sequence` row locked `FOR UPDATE` **inside the same transaction** as the entry insert. This serialises posting per journal per fiscal year — an accepted trade-off at school volume. A `SequenceGap` report and a nightly check assert `count(*) = max(piece_no)` per (journal, fiscal year). Pest test: a rolled-back posting consumes no number.

**Gaps permitted (atomicity only):** `receipt_no`, `invoice_no`, `matricule`, document series. Row-locked sequence table, never `max()+1`. **Uniqueness scope is stated explicitly per series** — v1 stated it for `piece_no` and left `receipt_no` ambiguous.

Generalised per-document-type series: `HA/2026/COM/000123`, `HA/2026/TRANS/000123`, pass numbers, card numbers.

`matricule` is globally unique, immutable once official. **One supervised exception:** the reference supports a *temporary* matricule prefix replaced by the official government number later. A single audited temporary→official transition is permitted; nothing else mutates it.

## 13. Document integrity policy

Two auditors disagreed here. The resolution is not "does it mention the Ministry" but **"does it purport to be issued by the State, or to certify a credential the school did not award."**

### 13.1 Permitted

The **bilingual state letterhead** — `RÉPUBLIQUE DU CAMEROUN / Paix – Travail – Patrie`, ministry name, regional and divisional delegation. This is standard Cameroonian school stationery; the school genuinely operates under MINESEC/MINEDUB supervision, and **every real Cameroonian bulletin carries it** (verified against a 6ᵉ APC specimen). A `state_header` block renders it, configured in `SchoolProfile`.

v1's carve-out banned this and would have made the product unable to print a normal report card.

### 13.2 Forbidden — permanently

- A **Ministry seal or stamp** on a school-issued document (the archived transcript mockup carries a blue *"SECRETARY / MINISTRY OF SECONDARY EDUCATION"* stamp)
- Signature blocks for the **Minister**, the **GCE Board Chairman**, or the **Director of the Office of the Baccalauréat**
- **Certifying award of a national credential the school did not award** — GCE O/A Level, Baccalauréat, BEPC, Probatoire. The archived diploma mockup states the student "completed the General Certificate of Education Advanced Level"; a private school cannot certify that
- National credential serial numbers, centre numbers, index numbers
- **Security-features legends** ("hologram", "UV feature", "microtext", "printed on special security paper")

Building these makes the product a credential-forgery tool and exposes the vendor and its customer schools to criminal liability. The .NET reference reached and documented the same conclusion.

### 13.3 Mockup deviation clause

**Three mockups for documents this product *does* deliver currently violate §13.2**, and an implementer following them would build what this section forbids:

| Mockup | Violation | Required change |
|---|---|---|
| `statement of results.png` | Reports **GCE A' Level** grades; ministry examinations-office seal | Report the **school's own internal results**; school stamp only |
| `certificate of completeion.png` | "EXAMINATION TYPE: GCE Advanced Level" | Certify completion of studies **at the school** |
| `Student ID V1/V2.png` | National coat of arms + ministry seal | School crest and letterhead only |

**Archived as unbuildable (6):** `Transcript.png`, `08_12_56`, `08_14_05`, `08_14_00`, `08_14_21` *(Minister-signed GCE diploma)*, `08_14_25` *(ministry-sealed GCE transcript)*.

### 13.4 Delivered instead

School-issued, under the school's own authority and signatures: Report Cards / Bulletins · **Statement of Results (school's own)** · **Academic Transcript (school-issued, multi-year)** · Certificate of Completion · Transfer Certificate · Testimonial / Character Certificate · Attestation of Attendance · Fee Receipts & Statements · Student ID Cards · Payslips. Full suite in `10-documents`.

### 13.5 QR verification

Every certificate points at a verification target, so one must exist. **LAN deployments have no public endpoint**, so the payload is a **self-contained signed token** verifiable offline, with an optional vendor-hosted public verification page for VPS deployments. Rate-limited, unauthenticated, revealing only document validity — never student data.

## 14. Audit & print logging

`AuditLog` — actor, `actor_name_at_time`, action, module, `auditable_type/id`, before/after (encrypted where the field is), IP, user agent, timestamp. **Append-only, and enforced**: hash-chained (`prev_hash`, `row_hash`), verified nightly, exported as a signed archive per period. "Immutable by convention" satisfies no auditor.

**A genesis-anchored chain is not enough, and this was proven empirically rather than assumed.** A chain anchored only at its start detects tampering and mid-chain deletion, but **not truncation of the tail** — delete the newest rows and the remainder is still a valid chain, so verification reports "intact". That is the deletion that matters most, because the newest entries are exactly the ones recording an intruder's actions. `AuditChainAnchor` is therefore a single row holding the expected head hash, entry count and last entry id, advanced inside the same transaction as every write, and checked by `VerifyAuditChain`.

The anchor does not make the log tamper-**proof** — someone with database access can update it too. It makes truncation tamper-**evident**, forcing an attacker to alter two places consistently, and it gives the backup job (`08-operations`) a small value to export off-box for external comparison. Hashing covers a **recursively key-sorted decode** of the payload, not the stored bytes: MySQL renormalises `json` columns on write (reordering keys, respacing, unescaping), so a byte-level hash cannot survive a round trip.

Partitioned/archived by year — at ~400 000 rows/year it becomes the largest table in the system. Retention: 3 years hot, then compressed archive. Indexed for the real query ("who changed this mark"), and paginated in the viewer.

`DocumentPrintLog` — every certificate, report card, receipt, payslip, ID card: who, when, which subject, **which snapshot version**, and whether it is a **duplicate** (reprints are watermarked `DUPLICATA`; two identical originals for one payment is a control failure).

## 15. Build order

Restructured. v1 put backup/DR and performance in "Phase 11 — Polish" and omitted licensing and deployment entirely, which meant a school would run live financial data from Phase 5 with no backup design.
